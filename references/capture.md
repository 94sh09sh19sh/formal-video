# 錄系統操作畫面

## 原則
- 被拍的系統只唯讀使用：用它自己的啟動腳本、展示環境、模擬資料介面；需要劇本化的資料（例：某位病人血壓慢慢下降）就餵它既有的模擬介面，不改它的程式。
- 先探查再寫錄影腳本：每一步截圖並列出畫面上的按鈕名稱（`aria-label` 或文字），錄影腳本用 `getByRole('button', { name })` 點，不用座標。
- 每次正式錄製前重建一份全新的資料（不然前一次試錄的求助、紀錄會出現在畫面上）。
- 全部用虛構資料；姓名用一般常見姓名比「測試甲」自然，但畫面上要有「展示資料皆為虛構」的標示（合成時加）。

## 先配音、再照旁白時間錄（不要先錄再剪來對時）
- 順序：`fv narrate` → `fv timeline`（產生逐字時間）→ 錄影 → 合成。錄影腳本用 `lib/narration.mjs` 的 `N.at('L09', '求助')` 查念到某個詞的全片秒數，減掉這一鏡的起點、加上錄影的預留秒數，就是錄影裡要按下去的秒數。
- 每一個會讓畫面改變的動作都排在「旁白念到它」的那一刻：`tap(page, locator, { rec, label, at })`。合成時錄影從頭連續播，不在動作之間剪接，畫面與旁白自然同步。
- 不寫固定的 `wait(8000)` 撐時間；兩個動作之間要多久由旁白決定（`rec.at(t)` 等到那一秒）。`rec.at` 印出「晚了 N 秒」時，表示前一步或系統反應太慢，要提早前一步或改稿。
- 系統自己會變的畫面（例：院方新紀錄進來、圖多一個點），也排在念到的那一刻觸發，並用 `rec.mark(label, { kind: 'change' })` 記下來。
- 一鏡錄得比旁白長一點：前面預留 1～1.5 秒、後面留到下一鏡開始後 0.5 秒，合成時有餘裕。

## 點擊要先被看見、才生效
- `installCursor(page)`（在 `goto` 之前）：畫面上的游標平常不出現；`tap()` 時從上一個位置滑過去（0.4 秒）、按壓（縮小＋擴散圈），**0.45 秒後才真的點下去**。舊做法在點下去的同一格才畫圈，觀眾看到圈時畫面已經跳走了。
- `tap()` 的標記同時記兩個時間：`at`（觀眾看到按壓）與 `click`（真的點下去、畫面開始換）。旁白對 `at`；標註框、版面切換對 `click`。
- 兩個畫面要同步（例：病人端與護理端）：兩個 recorder 同時 `start()`，以其中一個當時鐘排動作；合成時以各自 `.json` 的 `start` 對齊。
- 系統有延遲送出的動作（例：8 秒內可復原才真的送出）時，延遲期間就是旁白講下一句的時間；排程時把它算進去。

## 時間不對時：平移時鐘，不要等
- 被拍系統的畫面跟著真實時間走（時鐘、班別、跨日）而現在不適合錄（例：午夜前後、凌晨），把整套系統的時間平移到合適的時刻：
  - 後端與模擬服務：Node 行程加 `--require <工具>/lib/clock-shim.cjs`，環境變數 `FV_CLOCK_OFFSET_MS=<毫秒>`（建資料的腳本也要用同一個偏移跑）。
  - 瀏覽器：`await shiftClock(context, offsetMs)`，在 `newPage` 之前。
- 只平移 `Date`；計時器照真實速度走，所以錄影長度不受影響。偏移量寫進專案的 `decisions.md`。
- **先確認資料庫有沒有自己填時間**：ORM 或資料庫自己產生的時間（例：Prisma 的 `@default(now())`、`@updatedAt`，由查詢引擎讀作業系統時鐘）不會跟著平移，畫面上若顯示「建立時間」就會前後矛盾、依建立時間篩選的查詢也可能出錯。這種系統不要平移，改在合適的真實時間錄。

## 錄法
- `createRecorder(page, { outDir })`：DevTools 協定逐格 JPEG，每格帶時間戳，`stop()` 依實際間隔組成固定 30fps 的 mp4，並寫同名 `.json`（起訖、格數、標記）。
- `deviceScaleFactor: 1.5`：1280×800 的平板錄成 1920×1200，放大到全畫面也清楚。
- 要看清楚內容的畫面（例：護理紀錄）：先調捲動位置讓整張卡片在視窗內，必要時改用較窄的 viewport 讓文字變大，**不要在合成時硬放大到切掉一邊**。

## Windows 上的坑
- Git Bash 會把 `/路徑` 參數改成 `C:/Program Files/Git/路徑`；加 `MSYS_NO_PATHCONV=1` 時，輸出路徑要寫成 `C:/...`，不要寫 `/c/...`（會變成 `C:\c\...`）。
- Playwright 用系統的 Chrome：`chromium.launch({ channel: 'chrome' })`，不必另外下載瀏覽器。
- 開發伺服器以背景執行時，收尾要照埠號找 PID、`taskkill /T /F`，不然 vite 與 ts-node 會留著佔埠。
- 政府網站常有 Cloudflare 擋 `curl`／WebFetch：用有視窗的 Chrome（`headless: false`）開頁面讀文字；檔案下載連結（`dl-*.pdf`）通常 `curl` 就拿得到。
