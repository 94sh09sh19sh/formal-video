# 論述與稿

## 選結構
| 場合 | 結構 | 一句話 |
|---|---|---|
| 爭取採用、試用、資源 | 新創 demo：Hook → Problem → Solution → Demo → Traction → Ask | 問題要痛、示範要真、現況要可查 |
| 學術成果、研討會 | 背景 → 缺口 → 方法 → 結果 → 限制 → 下一步 | 限制要說，評審會問 |
| 產品介紹、教學 | 情境 → 一個完整任務從頭做到尾 → 重點回顧 | 一支片只教一件事 |

## 新創 demo 搬到機構內部（醫院、公部門、學校）時的改法
- Hook 用可驗算的具體數字（例：一週 3 次 × 4 小時 = 一年 624 小時），不用誇張形容詞。
- Problem 換成觀眾的 KPI：病安、人力、評鑑、法遵；市場規模換成本機構規模（沒有就整段拿掉）。
- Traction 只講可查證的事實：做完了什麼、驗收了幾項、裝到哪裡；「還沒做到」照實說。
- Team 多半省略（申請人本人在場）；片尾名單列計畫與開發者即可。
- Ask 在影片裡不出現或只說「下一步」，留給現場的人接話；不提錢時把相關字寫進 `bannedTerms`。
- 安全感比新奇感重要：講清楚「不做什麼」（不做診斷、不取代現行流程、資料不出機構）。
- 不宣稱成效數字，除非有上線前後的實測；只說「做得到什麼」。
- 展示資料全為虛構，畫面角落全程標示。

## 分鏡
- 一個完整情境當主軸，佔全片三分之一以上；兩端同步的事（例：平板按求助、護理站亮起）用左右分割畫面。
- 數字一張卡一個，出處小字在下方；圖從最簡單的版本長出來，被念到才出現。
- 避免：條列字卡、三張卡排一列、圓圈裡放圖示、旁白逐字重複畫面文字。
- 功能介紹不要只念名字快切：一個功能一句，講它讓誰得到什麼（例：「小花園，每來一次花就長大一點，讓人期待下一次再來」）；功能的作用要對得到被拍系統的設計文件，不寫醫療效果（「預防失智」「改善憂鬱」這類沒有實證的不說）。
- 每一鏡先寫「要觀眾看到什麼」一句話，畫面只留那件事；說不出來的鏡頭拿掉。
- 結尾一句話收在核心概念，不放品牌結尾卡，除非要求。

## 旁白稿（script.md）
- 一句一列，`編號` 用 L01、L02…；一句 ≤ 32 字。字幕依標點拆行，一段超過 `captionMaxChars` 時 lint 會要求在稿裡用「｜」標斷點（念的時候會拿掉）。
- 標點：旁白就是字幕，只用逗號、頓號、句號、問號、驚嘆號、引號；不用分號、冒號（lint 擋）。字幕顯示時逗號、句號換成全形空白（台灣字幕慣例），由 `fv timeline` 處理。
- 畫面要跟著換的詞（功能名稱、按鈕名稱）寫成稿裡實際念的字，錄影與合成用它查時間（`N.at('L16', '小花園')`）。
- 中文每秒約 4.2 字；2:40 的片旁白約 450～550 字，留給畫面的空白要夠。
- `念法` 欄處理合成語音念不準的字：英文縮寫拆開（AI → A I）、多音字換同音字、數字寫成念法。
- 有數字的句子 `引用` 欄一定要填，`fv lint` 會擋。
- 稿與畫面上的用詞照被拍系統的實際文字（先截圖確認，例：按鈕叫「我需要協助」就不要說「求救鈕」）。
